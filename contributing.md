Thank you for taking an interest in Gitamrta. Bug reports, careful testing, and clear improvement suggestions help the project owner understand what should be improved.

## Ways to help

Subject to the license, you can help in these ways:

- **Report a bug:** Describe what happened, what you expected, and how to reproduce it.
- **Suggest an improvement:** Explain the user problem and the proposed behavior. A suggestion is not permission to implement or distribute a modified version.
- **Test an official, unmodified release:** Check the search, randomizer, verse display, copy action, and theme controls, then report reproducible results.
- **Report scripture-data issues:** Identify the chapter/verse and describe which field appears to be missing or incorrect. The data comes from an external API, so distinguish an API response issue from a popup display issue where possible.
- **Review documentation:** Point out unclear, inaccurate, or incomplete instructions without republishing modified copies of the project files.

## Before reporting a bug

Please include:

1. Gitamrta version shown in `manifest.json`.
2. Chrome or Chromium version and operating system.
3. The chapter/verse reference, if the issue concerns a particular shloka.
4. The exact steps needed to reproduce the issue.
5. What you expected and what happened instead.
6. Any relevant error message from the extension popup or browser developer tools, after removing private information.

Check whether the issue is reproducible with the official, unmodified project files and a working internet connection. Do not include passwords, authentication tokens, personal information, or unrelated browsing data in a report.

## Responsible conduct

Be respectful and specific. Keep reports focused on Gitamrta, do not post exploit details publicly before coordinating a security report, and do not upload private user data or credentials. For suspected vulnerabilities, use the process in [`security.md`](security.md) rather than a public issue.
